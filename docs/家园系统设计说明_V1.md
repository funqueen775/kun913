# 熊心壮职 · 家园系统设计说明 V1

> Godot 侧实现依据。对应《0909 游戏机制与情绪价值设计说明 V1》§4.3 / §4.4 / §9 / §10 / §12，
> 与《记忆系统设计说明_V1.md》（后端口径）平行，不覆盖其接口约定。
> 铁律（机制文档原文）：**家园不提供能力、生命或测评加成；家具购买、摆放和消费不纳入职业画像。**

## 1. 现状盘点（本设计的四个结合点）

| 现有件 | 位置 | 与家园的关系 |
| --- | --- | --- |
| 宿舍 | `scripts/DormRoom.gd`（CanvasLayer layer 110，平时/宵禁两态） | 家园**寄生在宿舍**：DormRoom 从"一个按钮的黑屏"升级为"宿舍场景 + 陈列层"，不新建入口、不改流程 |
| 记忆便签链路 | `memo_recorded` → `user://workplace_town_memos.jsonl` → `MemoryWallPanel`（eventId 去重、worldMinute 排序、老存档回填） | 纪念物**复用这条链**：纪念物 = 记忆便签的实体化陈列，文案唯一来源仍是 memos/事件数据 |
| 月度经济 | `scripts/MonthlyLife.gd` `_settle_month()`：工资 10000 + 奖金(0~1500) − 支出 6500，开局 15000 | 家具是**唯一大额金钱出口**：每月结余 3500~5000，48 个月累计约 18~25 万 |
| 隐藏好感度 | `MonthlyLife.affinity`（0-100，对玩家隐藏）+ 知心时刻门槛 40 | NPC 到访的触发条件直接复用，不新增关系数值 |

`MonthlyLife.gd` 注释里"家具/欠款系统不在 MVP 范围"由本文件正式解除：家具购买进入范围，欠款仍不做（机制文档 §4.3 维持：只有特殊剧情欠款，下月工资优先偿还）。

## 2. 设计原则（改设计前先读）

1. **零 buff 是数据结构问题，不是口头约定。** 家具目录里不存在任何数值字段（没有 skill/health/energy 键），自检脚本断言这一点，而不是靠 UI 不显示。
2. **文案单一来源。** 纪念物、到访台词全部是"引用 + 模板槽位"，不新增一段与事件数据平行的叙事文案。LLM 只允许润色且必须有模板降级（与记忆系统设计说明 §8 同一口径）。
3. **家园数据不进事件流水。** 购买/摆放/到访只写家园自己的存档文件，不写 `workplace_town_events.jsonl`、不进 `ApiClient.record_event` 的测评埋点 —— 这是机制文档 §10 防污染规则在存储层的落地形式。
4. **陈列位制，不做像素自由摆放。** 预设槽位 + 拖放吸附。理由：自由拖拽（吸附、碰撞、多分辨率、布局序列化）成本高且多数玩家最终摆法趋同；槽位制把摆放从"操作问题"简化为"选择问题"，情绪价值不减。

## 3. 家园场景：DormRoom 升级

### 3.1 三种状态

| 状态 | 进入方式 | 行为 |
| --- | --- | --- |
| 平时（出门） | 现状不变 | 玩家**自己走到蓝色双开门前**，弹确认框「现在出门？」→ 点「离开宿舍」才出门 |
| 宵禁（23:00 后） | 现状不变 | 人被送回宿舍门口，**自己走回卧室门口**，弹确认框「上床睡觉？」→ 睡到次日 07:00 |
| **在家（新增）** | 平时状态点"布置一下"按钮 | 进入陈列模式：浏览/购买/摆放家具与纪念物；随时点"出门"回到平时状态 |

宿舍屏自 2026-09-16 起是**可走的**：`DormRoom` 里有个底图坐标系容器，
站位由 `assets/town/dorm_walkable_mask.png` 判定（`tools/build_dorm_walkability_mask.py`
从底图地板色 + 矩形白名单算出来）。因此：

- 摆放槽位坐标沿用**底图归一化坐标**（0~1），和 `_room` 那一层缩放解耦，换分辨率不用重算；
- 摆出来的家具要进掩膜（`BLOCKERS`），否则玩家会直接穿过去；
- 家里的可走范围就是大厅 + 门厅 + 卧室门口三段，扩展时往 `REGIONS` 加矩形即可。

在家模式不消耗精力、不推进时间（不调 `WorldClock.advance_minutes`）。宵禁的夜色压屏表现不变，
等美术图到位后只改 `DORM_IMAGE_PATH`，陈列层叠加在背景图上。

### 3.2 陈列位

槽位坐标集中写在 `data/town/dorm_layout.json`：

```json
{
  "floor_slots":  [{"id": "F01", "x": 0.22, "y": 0.78}, {"id": "F02", "x": 0.38, "y": 0.78}],
  "wall_slots":   [{"id": "W01", "x": 0.30, "y": 0.35}],
  "relic_rack":   {"x": 0.72, "y": 0.35, "capacity": 8}
}
```

- `x/y` 为背景图相对坐标，美术图交付后按实际构图微调数值即可，不动代码。
- 交互：拖家具图标到空槽吸附；点已摆放的家具弹出"收回/换位"；纪念物**不可购买、不可收回**，只能上/下架纪念架。
- MVP 建议 floor 6 格、wall 3 点、纪念架 8 位（48 个月主线 + 知心时刻的纪念物产出上限约 12，超出部分进"抽屉"列表翻页，不丢）。

## 4. 家具目录与职级曲线

### 4.1 目录文件 `data/town/furniture_catalog.json`

```json
{
  "id": "coffee_machine",
  "name": "咖啡机",
  "slot_type": "desk",
  "price": 2600,
  "tier": 2,
  "desc": "救火那阵子全靠它撑着。",
  "sprite": "",
  "visit_tags": ["overtime"]
}
```

- `sprite` 留空 = 占位色块（沿用 `ResourceLoader.exists()` 静默退占位的既有惯例；新 PNG 必须 `--import`）。
- `visit_tags` 是 NPC 到访台词的匹配键（§6）。
- 目录是纯静态数据，**任何字段不得被解读为加成**（原则 1）。

### 4.2 三档职级曲线（对标现金流实算）

每月可支配结余 = 3500（无奖金）~5000（奖金封顶）。三档设计让"钱够但要不要花"始终是取舍：

| 档 | 解锁 | 单价区间 | 内容基调 | 档内总预算 |
| --- | --- | --- | --- | --- |
| 1 合租档 | 第 1 月 | 400~1500 | 二手、折叠、多功能 | ~8000 |
| 2 独立档 | 第 13 月（一年转正节点） | 2000~6000 | 像样的床、咖啡机、书架 | ~20000 |
| 3 改善档 | 第 31 月（重构/平台化阶段前） | 8000~18000 | 大件：沙发、好椅子、相机 | ~30000 |

- 全档总计约 5.8 万 ≈ 48 个月累计结余的 25%~32%，剩余空间留给"买不起 → 攒两个月"的取舍感，避免一次性装修完后家园断档。
- 档位解锁只放宽"能不能买"，不自动送任何东西；晋升失败不降档（家园是安全区，不做惩罚性反馈）。
- 数值平衡属 §13 待确定项，试玩后只调 `price` 与档位边界，不动结构。

## 5. 纪念物：记忆便签的实体化

### 5.1 数据链路（不双写文案）

```text
data/story/*.json 的 MAIN_EVENTS（在 memoryNote 旁新增 "relic": {"name": "...", "desc": "..."}）
        │  事件结算（outcome_acknowledged）时
        ▼
user://workplace_town_relics.jsonl   ← 追加 {"eventId", "relicId", "npcId", "source", "worldMinute"}
        │
        ▼
DormRoom 陈列层读回（按 eventId 去重，同 MemoryWallPanel 惯例）
        │  点开纪念物
        ▼
展示故事卡：relic.desc + 该 eventId 对应的记忆便签原文（复用 _memo_from_catalog 回查）
```

- 文案唯一来源是事件数据与 memos；`relics.jsonl` 只存**引用**，删掉也不丢故事（下次结算重放即恢复，同"记忆是投影"哲学）。
- `source` 取值：`main_event`（主线关键事件）/ `intimate`（知心时刻，复用 `can_trigger_intimate` 门槛 40，一次性）/ `story_gift`（剧情赠礼，后续剧情册按需标注）。
- 老存档兼容：`relics.jsonl` 不存在 = 空起步，不崩溃；已结算过的主线事件不做追溯补发（避免打开游戏突然满架，追溯开关留给后续版本）。

### 5.2 与记忆墙的分工

- 记忆墙 = 时间流（"这四年发生了什么"），保持现状不动。
- 家园纪念架 = 空间流（"这些事留在了我的生活里"）。
- 两者共享 eventId 底座：记忆墙铺满的瞬间，就是纪念架摆满的瞬间，情绪互相增强而不是两套系统各说各话。

## 6. NPC 到访：家园的"读取侧"

### 6.1 触发判定（在家模式进入时跑一次）

条件全部成立才触发，按顺序取**最多一名**访客：

1. `affinity >= 40`（知心门槛，同 `can_trigger_intimate` 口径）；池限四名核心 NPC（`SOCIAL_POOL`），熊总/陈工不到访；
2. 冷却：该 NPC 距上次到访 ≥ 4 个游戏月（冷却记录写进家园存档，不建新表）；
3. 可引用素材：该 NPC 在 memos 中至少有一条带其 `npcId` 关联的便签，或玩家家中有其 `visit_tags` 匹配的家具；
4. 优先级：匹配到家具的素材 > 纯记忆素材（看到具体东西的台词更自然）。

### 6.2 台词生成（模板优先）

模板槽位 = `{npc}` + `{家具名/纪念物名}` + `{fact 引用}`，降级顺序与记忆系统设计说明 §8 一致：

- 模板例（王哥 + 咖啡机 + 线上事故便签）：
  "还留着这个？那年救火，全靠它撑着。——你现在身体还好吧。"
- LLM 只许改写措辞，校验关键槽位仍在句中，失败退模板；`generatedBy` 标记来源。
- 到访**不消耗精力、不改好感、不进测评**（防刷三禁）。同一便签被引用过后打 `visited` 标，短期内不重复引用（同记忆系统验收 §11.1 精神）。

## 7. 存储

| 文件 | 内容 | 写法 |
| --- | --- | --- |
| `user://workplace_town_home.json` | `{"owned": [...], "placed": {"槽位id": "家具id"}, "visit_cool": {...}}` | 整文件覆盖写（小文件，快照语义） |
| `user://workplace_town_relics.jsonl` | 纪念物引用流水 | 追加 + eventId 去重（同 memos 惯例） |

- 购买动作：`MonthlyLife.money` 直接扣减（家具是现金购买，无赊账），`state_changed` 广播让精力面板/时间面板同步。
- 存档恢复：重进游戏按文件重放陈列状态；`relics.jsonl` 丢失自动按已结算事件重放（原则 2 的确定性要求）。

## 8. 测评边界落地清单

| 行为 | 存储 | 进事件流水 | 进埋点 | 进报告 |
| --- | --- | --- | --- | --- |
| 购买/摆放家具 | home.json | ✗ | ✗ | ✗ |
| 纪念物生成 | relics.jsonl | ✗（主线结算本身已在 events.jsonl，relic 只是投影） | ✗ | ✗ |
| NPC 到访 | home.json visit_cool | ✗ | ✗ | ✗ |

抽查验收（同记忆系统设计说明 §11.6 的形式）：`workplace_town_events.jsonl` 与 `ApiClient` 流水中不存在任何以 `home` / `relic` / `visit` 为前缀的记录。

## 9. 分期与验收

### 9.1 分期

| 期 | 内容 | 依赖 |
| --- | --- | --- |
| H1 | catalog + dorm_layout + 槽位摆放 + 购买扣款 + 纪念物自动上架（模板文案） | 无（占位色块起步） |
| H2 | NPC 到访 + 职级三档解锁曲线 | H1 |
| H3 | LLM 润色到访台词 + 家园氛围一句文案 | H2 + 后端 M4 |

### 9.2 自检（沿用探针惯例）

`build/probe_home.gd`（extends SceneTree，数检查项并设下限，防循环假通过）：目录零数值字段断言、槽位全覆盖、购买扣款与余额、relics 去重与重放、老存档空起步、到访冷却与三禁。

### 9.3 体验验收（补机制文档 §12.3 家园缺口）

1. 玩家是否每月至少主动"回家布置"一次？（到家访埋点的 game-only 统计）
2. 目录里任何字段能否被解读为加成？（应全部为否）
3. 不买家具、不回家的玩家，主线与报告是否完全不受影响？（对应机制文档 §12.3 末条）
4. 纪念架摆满时，玩家能否说清至少三件纪念物"是谁、因为什么"留下的？
