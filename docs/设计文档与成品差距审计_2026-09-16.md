### 1.4 产品内部自相矛盾：导览页对玩家说了假话

### 1.5 精力：文档「每月 3 点」，成品「每天 4 点」

| 项 | 文档口径 | 成品口径 | 证据 |
|---|---|---|---|
| 精力 | 每月 3 点，不可结转，1 点 = 1 项**月度**养成行动（算法册全局参数表 / 机制文档 §4.1） | `ENERGY_PER_DAY = 4`，**每天** 4 点，睡一觉（跨天）回满 | `scripts/MonthlyLife.gd` L16 |
| 界面 | 公开数值里的「精力」 | 显示成「今日体力 · 第 N 月」 | `scripts/EnergyPanel.gd` L287 |

**这是测量口径的根本分歧**：算法册「投入结构」「精力管理」两个报告模块，样本来自「每月的精力怎么分配」；做成了日行动力之后，你统计到的是「今天先干什么」，两个量纲对不上。而且「一个月 3 次机会」的稀缺感没了，取舍压力也没了。

### 1.7 奖金：量级差一倍，推导源还踩了红线

- 文档：`bonus_tier` 由 **O（开放性，隐藏层）** 推导，三档 **0.3W / 0.1W / 0**（打分卡 `_anchor_params`）。

踩的是算法册 §8.2 第四条红线「奖励不指向唯一最优解」——**现在钱和「产出」直接挂钩，玩家会为了钱去刷产出**。而算法册明写「结果类证据只采『是否达成目标』，不采『拿到多少钱』」。

### 1.8 自由活动解锁档位锁死，3 个活动永久玩不到

`scripts/FreeTimePanel.gd` L87：

```gdscript
const CURRENT_GAME := 1
```

V5.27 §一：总时长约 100 分钟，**分 3 局（每局约 33 分钟）**。`free_time_system.json` 和美术需求单都按 game1/2/3 安排了解锁与美术优先级。成品是一局从第 1 月跑到第 48 月，没有局的概念——所以 1.8 的锁死不是「还没做」，是「做了一半，另一半的假设已经不成立」。

- 同一件事（E04 技术选型）存在两份内容不一致的副本：`data/story/task_001_tech_stack.json` 一份、`WorldClock.gd` 一份。

### 3.2 【最严重】剧情演出差异化 = 0，24 件共用一个弹窗模板

- 只有 `M1-E01` 迁到了 beats 分镜（`WorldClock.gd` L38–L47，含 narration / say / interact / choice 拍）。
- **E02–E24 全部只有 `story + prompt + choices + outcome`**，走同一个 `StoryEventPanel` 模板。
- 美术需求单为 44 个节点各写了完整的：出场角色站位与进出场、剧情道具的初始位置与前后状态、可交互物及其「是否永久改变场景」、场景变化（灯光/物品/记忆墙）、三个分支的差异类型（改道具 / 改场景 / 改动作 / 改台词）、镜头语言、UI 需求。
- **这些一条都没实现。** 玩家玩 48 个月，看到的是 24 个长得一模一样的对话框，只有字在变。文档里「每场戏结束场景必须留下点什么」的设计意图 100% 落空——**选择对世界没有留下任何痕迹**。

### 3.3 自由活动把「选人」砍掉了 —— 砍掉的正好是测量目标

`scripts/FreeTimePanel.gd` L11 注释：

> 「选人环节 MVP 不做（用户拍板）：双人/团建活动的同行 NPC 由系统随机指派。」

但 V5.27 §11.6 明写：

> 「更纯的偏好暴露：无场景压力、无对错，**把周末给谁是本能选择**」；「社交指纹 2.0：三维轨迹（去哪组团 × **和谁** × 活动类型），输出四种社交画像——独处型 / 深谈型 / 玩乐型 / 聚会型」；「好感度 vs 六维交叉：**你嘴上嫌他，周末却总往他那跑**」。

随机指派之后，「和谁」这一维直接变成噪声。**这不是省略一个交互细节，是把两条核心测量（投入结构、社交指纹）删掉了**，同时让算法册 §5 的 `3e 投入结构 = work 型占比 × 自愿系数` 失去一半输入。

### 3.4 公开数值面板少了三项，且少了最关键的一项

- 文档要求公开 6 项：专业能力、生命、精力、金钱、**职级**、**关系阶段**。
- `scripts/EnergyPanel.gd` L164–L166 实际只展示：专业能力、生命、金钱（+ 今日体力）。
- **职级不显示** → 玩家不知道自己在职场的什么位置，「我在成长」这条主体验断腿；**关系阶段不显示** → 机制文档 §5.4 要求「前台展示关系阶段及进度感」，成品只有一个 0–100 的隐藏好感（`MonthlyLife.AFFINITY_MAX` L24），玩家完全感知不到关系在推进。

### 3.5 打分卡的公开层字段全部无人消费

算法册 §九 专门补了三个跨层接口：`life`（生命，15 处）、`prof`（公开专业能力，20 处）、`bonus_tier`（123 处全覆盖）。
成品里：**Godot 不读打分卡**（红线如此），但**也没有任何一层把这三个字段接到公开数值上** —— `MonthlyLife` 的 skill / health 变化只来自 `spend_energy` 与结算，与玩家的剧情选择完全无关。
→ 「选择 → 公开数值变化」这条「可见反馈」支柱（机制文档 §1.2 第二个设计支柱）在成品里**不成立**。

### 3.6 记忆墙只有两种颜色，且只有一种来源

- `MemoryWallPanel.gd` + `user://workplace_town_memos.jsonl`，便签只有 **金 / 灰**。
- 美术需求单要求「蓝色→黄色→金**按好感度渐进**」——没做。
- C1「第一次 done」、C2「第一通」、C3「压住了 / 蒙过去了」（按前置 flag 二选一）、D6「那把伞」等**专属便签**——因为成就节点和 D6 都没做，全缺。
- 便签唯一来源是主线 `outcome` 里的 `memoryNote`。

### 3.7 区域命名两套并存，还有错别字

| 来源 | A 区名称 | B 区名称 |
|---|---|---|
| `data/town/regions.json` | 熊起东方总部 | 云栖科技丘 |
| `scripts/WorkplaceTown.gd` L89–L98 | 「启程广场·**飓**起东方总部」（错别字） | 云栖科技**工厂** |

V5.27 §三 的口径是「启程广场·熊起东方总部」。铁律里「演员表唯一来源 `data/town/npcs.json`」的精神同样适用于区域——**现在区域有两份不一致的定义，没有唯一来源**。

### 3.8 NPC 名单里有一个悬空 id「熊总」

- `data/town/npcs.json` 是 5 人：王哥、陈工、小林、老周、小赵（陈工 `relation=false`，不进关系系统——这条口径已经在文档里写清了，是对齐的）。
- 但 `scripts/MonthlyLife.gd` L28–L34 的 `NPC_NAMES` 里有独立的 `"xiong_zong": "熊总"`，好感度字典会给它开一格；而 `SOCIAL_POOL` L36 又只有 4 人。
- V5.27 §三 已裁定「**熊总 = 老周 / 大领导**」→ 现在系统里多了一个不存在的人物档案。

### 3.9 活动落地区域与文档不一致

`D1_coffee_chat` 在 `free_time_system.json` 里 `zone = C_水巷`，界面名叫「食堂约饭」。但美术需求单 3.2 与 V5.27 §三 都写 **D1 = 「B 科技丘 食堂」**。名与地对不上。

### 3.10 web/ 前端原型与 Godot 开场在重复劳动

- `web/src/screens/` 有 `EntryScreen` / `TitleScreen` / `TownIntroScreen` 三屏 + `web/src/api/report.ts`。
- Godot 侧 `StartupFlow.gd` 也有一整套「标题页 + 导览三页」。
- 两条前端线在做**同一件事**（开场 + 导览），而且 Godot 那份已经接到 `MainMenu`/`Guide`，web 那份的定位（按旧备忘是「只验版式」）没有在代码里体现。**这是一处明确的资源重复**。

### 3.11 自检体系只守卫「已经做了的东西」

`build/` 有 18 个 probe + `tools/` 一堆校验脚本，质量不错。但：
- **没有任何探针覆盖「24 件 vs 44 节点」的对账**（`story_key_map.json` 是对账表，但没有探针守着它不退化）；
- 没有任何探针覆盖训练谷 / 家园 / 报告 / 职级——**因为这些东西不存在，所以也没有守卫**；
- `probe_story.gd` 只测结构不变量（有没有 beats / choices / outcome），测不出选项方向反了。
