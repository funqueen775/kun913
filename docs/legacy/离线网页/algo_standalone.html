熊心壮职 · 报告数据链路与算法设计 V1

配套：主设计文档（引擎与机制）V1.5、剧情设计详细方案 V2。 本文档回答一个问题：报告里那些数字，是怎么从玩家的一次点击一步步算出来的。

核心主张：报告里没有一句空话——每一个结论都能点开看到支撑它的原始行为记录（行为证据链）。

一、四层架构总览

层 叫什么 在哪算 内容
L1 原始行为 前端只上报这个 裸点击、裸时间戳，不含任何计算
L2 派生特征 服务端 犹豫、横跳、分配向量、探索向量、冲刺差分
L3 判定指标 服务端 六维能力、大五后验、职业匹配度、晋升三层
L4 报告映射 服务端 报告每个模块 ← 哪些 L3 ← 哪些证据编号

红线（主文档已定，此处重申）：L1→L2→L3 全在服务端。前端永远只上传原始行为，抓包拿不到任何标定答案——前端算分等于把答案发给客户端。

3.1 V5.4 新增特征如何进入三层算法

新特征 进入哪一层 怎么用 报告落点
input_vector（投入结构） 第三层（3e 新增） 与岗位「日常活动构成」对照：技术岗的日常工作投入占比 vs 玩家的 work 型投入占比 交叉提示层：「你比自评里更想干这行」
intrinsic_motivation 第三层（3e） 职业适配的补充信号，不是人格分——只用于「适配提示」，不进大五 交叉提示层，标为「提示非结论」
attribution_style 第一层（BARS 编码） 危机对话的四个选项本身就是归因方式的标志行为，marker=attribution，loading 参照 N 维与抗压元分析 大五剖面的 N 维证据（仅卡住玩家）
survival_trajectory 晋升三层的行为层（20%） 已有：隐瞒 flag / 事故 / 谈话表现；生存轨状态是其可视化结果 处境轨迹模块（一层）
achievement_engagement 不做人格推断 仅做报告彩蛋与沉浸度（是否跳过成就节点） 报告「那些你停下来看的瞬间」
babysit_load / zone_preference 不做人格推断 日常质感与空间偏好，明确不参与任何评分 彩蛋，避免测量过载

一条红线：新增特征里只有 attribution_style 进人格推断，其余只用于「适配提示」或「彩蛋」——防止测量目标漂移（加什么都要往人格上算，是测评产品最常见的失控）。

四、L3 第一层：选项 → 行为编码（用心理学模型，不拍脑袋）

现在的做法（错的）：选项直接标 D+2。 正确的做法：选项标注标志行为 + 关联强度 + 情境强度，由模型算分。

4.1 每个选项标注三个字段

字段 含义 例子（第 3 月 AI 代码标注 · 选 B"不标注"）
marker 这个行为是哪个大五特质的标志行为 C 尽责性（走捷径）
loading 关联强度（0-1），来自元分析 0.40
situation_strength 情境强度（强/中/弱） 弱（没人检查你标没标注）

4.2 loading 从哪来：真实元分析（不是编的）

学界用大五预测工作绩效的元分析相关系数（ρ，已校正测量误差）：

大五维度 Barrick & Mount (1991) Sackett et al. (2022) Salgado (1997, 欧洲) 归一化 loading
C 尽责性 .23 .21 .25 1.00（基准）
情绪稳定性 .13 — .19 0.57
A 宜人性 .12 — — 0.52
E 外向性 .10（对管理者 .18） — — 0.43
O 开放性 .06（对培训 .25） — — 0.26

归一化方法：loading = ρ ÷ 0.23（以预测力最强的 C 为基准 1.0）。

分情境提升（学界发现"特质-效标匹配时效度更高"，Tett et al. 1991）： - E 外向性在管理/销售/社交情境 → 0.78（ρ=.18/.23） - O 开放性在培训/创新情境 → 1.09（ρ=.25/.23） - 情绪稳定性在高压情境 → 0.83

4.3 情境强度系数（第二个乘子）

心理学情境强度理论：强情境（有明确规范、有人看着）会压制人格表达，此时行为趋同、对特质推断的信息量低。

情境 系数 例子
弱情境 ×1.0 第 3 月 PR 标注（无人检查）
中情境 ×0.75 第 7 月评测集（工期紧但有选择空间）
强情境 ×0.5 第 30 月高管汇报（领导在场、规范明确）

加权载荷 = loading × 情境系数 × 方向（+/−）

五、L3 第二层：行为 → 大五后验（贝叶斯更新）

5.1 公式（逐符号翻译）

后验特质分 = 自评分 + K × (行为分 − 自评分)
  • 自评分：建档 4 题自评（0-10）
  • 行为分：所有相关选项的加权载荷均值映射到 0-10（5 为中性）
  • K：信任系数 = n / (n + 5)，n = 该特质有效行为样本数
  • n=0 → K=0（全信自评）；n=5 → K=0.5；n=20 → K=0.8（更信行为）

这是标准的贝叶斯收缩：样本少时向先验收缩，样本多时以行为为准。它同时把"自评 vs 行为"这个产品爆点数学化了。

5.2 完整演算（小陈的尽责性 C）

第 1 步：收集 8 次相关选择

# 事件 选项 方向 loading 情境 加权载荷
1 N3 第3月 AI 标注 B 不标注 − 0.40 弱 ×1.0 −0.40
2 T2 第7月 评测集 B 先不建 − 0.50 中 ×0.75 −0.375
3 R3 安全漏洞 C 拖着 − 0.50 弱 ×1.0 −0.50
4 C5 高管汇报 B 报喜藏忧 − 0.35 强 ×0.5 −0.175
5 M2 文档化 B 留一手 − 0.25 中 ×0.75 −0.19
6 T4 热修复 B 绕过流程 − 0.30 强 ×0.5 −0.15
7 P4 好友打分 A 按事实打 B + 0.35 强 ×0.5 +0.175
8 T1 技术选型 A 自己搭 demo + 0.40 弱 ×1.0 +0.40

求和 = −1.215，平均 = −0.152

第 2 步：映射成行为分

行为分 = 5 + 平均载荷 × 10 = 5 + (−0.152 × 10) = 3.5

第 3 步：贝叶斯更新（自评 C = 7，n = 8 → K = 8/13 = 0.62）

后验 = 7 + 0.62 × (3.5 − 7) = 7 − 2.2 = 4.8

第 4 步：矛盾度

矛盾度 = |自评 − 后验| = |7 − 4.8| = 2.2  → 超过 1.5，判定"显著矛盾"，进报告 C 位

5.3 信度：跨情境一致性

用 Mischel 的 CAPS 理论（人格是「如果-那么」模式）：同一特质在不同情境下是否一致。 - 一致 → 高信度，报告可下断言； - 不一致 → 报告写"你的 X 是有条件的"（例如：评审会上敢说、客户现场不敢说 = 外向性依赖情境）。

这比给一个死分数诚实得多，也是我们的差异化。

6.3 3c：匹配算法（优势维度 + 理想点维度分开）

不能用纯余弦相似度（那是"越多越好"的优势模型）。学界对职业匹配更准的是理想点模型——某些维度越过理想值反而扣分。

单维度贡献 = 权重 × (1 − |实际 − 理想| / 容忍度)
  • 优势维度（技术、尽责等）：理想点设为上限，等效于"越高越好"
  • 理想点维度（外向性、宜人性等）：设中间值，过高过低都扣分

代入演算（承接小陈 C=4.8）：

职业 C 的理想点 权重 容忍度 自评 C=7 时 修正后 C=4.8
A · Agent 后端开发 7.0 0.25 3.0 0.25 × 1.00 = 0.250 0.25 × 0.267 = 0.067
B · AI 技术产品经理 5.5 0.15 3.0 0.15 × 0.50 = 0.075 0.15 × 0.767 = 0.115

假设其他维度不变（A 总 0.78、B 总 0.70）：

只看自评 行为修正后
A 后端开发 0.78（第 1） 0.60（第 2）
B 技术产品经理 0.70（第 2） 0.74（第 1）

排名反转。 一个"第 3 月随手不标注"的选择，通过 8 次同类行为的累积，最终把职业推荐第一名换掉了。

6.4 3d：输出带真实市场数据（最有杀伤力的一环）

因为数据里有薪资、职级、经验、学历，报告可以输出：

Top1 · UI 设计师（A 艺术型 · 智联编码 Z050104） 该类型市场月薪中位 7,000 元（基于 95 条真实在招 JD） 63% 的同类岗位要求「沟通能力」，32% 要求「审美能力」

真实薪资 + 真实要求，比任何编的推荐都硬。

6.5 3e：投入结构与内在动机（V5.4 新增，补上「凭什么说他适合」）

第三层原本只有「画像 vs 岗位要求」，仍缺一个关键信号：他到底想不想干这行。补上 3e：

投入结构占比 = 该类自由活动次数 ÷ 16
内在动机指数 = work 型占比 × 自愿系数
  自愿系数：W 类（自己想做）= 1.0；S4 加班（卷公司的活）= 0.6

代入：小陈 16 个周末，9 次 W 类（其中 2 次 S4 加班）、1 次社交、6 次独处恢复 → work 型占比 = 9/16 = 56%，自愿系数 ≈ (7×1.0 + 2×0.6)/9 = 0.91 → 内在动机 ≈ 0.51（中高）。

对照真实 JD：Agent 岗对「学习能力/自驱」的要求占比 XX% → 交叉提示：「没人要求的时候你也在学——这比自评里那句『我对 AI 感兴趣』可靠得多。」

红线：内在动机只作适配提示，不进大五、不算人格分、不用于断言「你适合/不适合」。

6.6 统一打分卡：每个选项必填 9 组字段

现在的问题是每个选项只打了「六维 + 能力 + 大五」三样，且没有统一规格——加的内容越多越容易乱。统一为一张打分卡：

# 字段 量纲 用途 必填
1 state_delta S/O/N/H/D/R 增减 游戏内经济（晋升累积层输入） ✅ 必填
2 competency 12 键 ± 能力雷达 ✅ 必填

6.7 六个补充心理学模型（补大五测不到的面）

大五只回答「你是什么样的人」，回答不了「你为什么这么做、你在乎什么」。以下六个学界成熟模型补的正是动机与价值观——职业适配最需要的一层：

七、L4 报告：三层结构与呈现原则

7.1 为什么分三层（解决「凭什么说你适合」）

游戏测的是职场处世（怎么应对甩锅、会不会糊弄、扛不扛压），而「适合什么职业」是另一件事——中间不能硬凑因果。因此报告分三层，每层标明自己的数据来源与可信度：

层 回答什么 数据来源 可信度
第一层 · 职场人格画像 你在职场里是什么样的人、什么情境下会变形 48 个月游戏行为（贝叶斯后验） 高——真正测出来的
第二层 · 岗位市场参考 真实岗位要什么、薪资多少、什么职级在招 5000 条真实 JD + 建档自评 中——市场数据，不是心理测评
第三层 · 交叉提示 你的画像 vs 真实岗位要求 = 差在哪 前两层叠加 提示，非结论

定位一句话：不做「测出你适合什么职业」（断言，答不出凭什么），做「让你看清自己是什么样的人，以及真实岗位要什么——差距在哪」（描述 + 对照，每句可溯源）。初心不变，逻辑闭合，且评委那句「你凭什么说适合」自动消失。

7.2 呈现原则（V3 新增）

可观测的事实给死数字（行为次数、时长、市场薪资、要求占比）；推断值给档位与对照、不给点值；一切隐藏机制的阈值永不出现；差距一律翻译成行为语言。

内容类型 呈现方式 理由
行为证据 完全具体：次数、毫秒、事件名 发生过的事实而非推断——这才是最难反驳的「数据证明」
特质推断（大五/能力） 不给点值：五档词（很低/偏低/中等/偏高/很高）+ 条形 + 自评/行为双条对照 ① 虚假精确（n≈8 的推断值给 4.8 是假精确，评委一问置信区间就穿）② 诱导装（给分 = 教玩家下次演，亲手毁掉测量）③ 伦理（心理数据贴数字标签有伤人风险）
市场数据 给死数字：月薪中位、要求占比 客观事实，越具体越有用，也是我们的差异化优势
差距 翻译成行为语言，不给数值差 「差在没人监督时的那几次」比「差 2.2 分」更能让人改变
晋升/风险阈值 永不出现 红线：玩家知道阈值就会堆数值，测量当场失效

「用数据证明」靠行为证据，不靠分数： - ❌ 给分数：「你的尽责性 4.8，低于岗位要求的 7.0」 - ✅ 给证据：「8 次可以抄近路的地方，你抄了 6 次——第 3 月的 PR、第 7 月的评测集、还有那个没人知道的安全漏洞」

分数可以质疑「你怎么算的」，但「第 3 月那次你 4 秒就选了」是铁打的事实。这才是「过程即测评」的真正落地。

若评委问「为什么不给出分数」，标准答案：「我们的特质值是行为推断，给出 4.8 是虚假精确；我们选择给可验证的行为证据——『八次抄了六次』比一个分数更难反驳，也更能让人改变。」

十、方法局限与校准计划（诚实边界 2.0）

知道自己每一处不严谨、且每处都有校准方案——这比「没有局限」更是成熟度信号。本节按严重程度分三级。

10.1 🔴 严重级（答辩风险点，必须处理）

问题 1：loading 的绝对数值是设计假设

元分析给的是「特质 → 工作绩效」的相关（ρ=.23 等），而算法实际需要的是「某个行为 → 特质」的证明力——两者方向不同，不能直接换算。因此 loading=0.40 这类具体数值与情境系数（×0.5/×0.75/×1.0）没有直接文献支持，属于「相对排序有据（元分析方向）、绝对数值自定」。

对策：① 全文措辞已按此降级表述（"相对排序依据元分析，绝对数值为设计假设，需内测校准"）；② 内测做敏感性分析——把 loading 全体 ±50% 重跑，检验报告结论是否翻转：不翻转说明结论稳健（对参数不敏感），翻转则说明对参数依赖过重、需扩大行为样本。

问题 2：缺少效标效度验证（方法论生死线）

目前的「标定值 vs 实测值对账」（第 16 节报表二）是同一引擎内的自证，不是独立验证。新尺子造出来了，但还没和公认的老尺子对过。

对策（已写入主册 §22 内测排期，硬环节）：内测玩家同步完成 BFI-44 标准大五量表，计算游戏测分与量表分的相关： - r ≥ 0.4 → 方法可用，写入 PPT（"行为测评与标准量表显著相关"，可发表水平的证据）； - r ≈ 0 → 方法需大改。越早知道越好。

问题 3：角色扮演效应

玩家在游戏里扮演"Agent 开发师"，选择可能基于"剧情怎么发展"而非"现实中我会怎么做"——测到的可能是「他怎么玩游戏」。

对策：① 报告措辞限定为「职场决策倾向」，不做人格断言（已定）；② 重玩稳定性校验：同一玩家两次游玩的行为模式相关 <0.4 时，报告自动降低置信表述；③ 保留秒选/攻略式快选检测（真倾向与"查攻略快选"的时间特征不同）。

10.3 🟢 已接受的边界（原六条，保留）

10.4 伦理边界（比赛可接受，商业化前必须补全）
