熊心壮职 · 五模块结合设计 V1

配套：主册（引擎与机制）V1.5、剧情册 V2、算法册 V1、美术方案 V2.2。

本文档只回答一个问题：事件系统、游戏机制、美术设计、数据埋点、记忆系统这五个，怎么咬合在一起。

一、五者不是并列关系

把这五个当成平级模块是最大的误解。实际结构是一条主链 + 一个横向层 + 一个并联层：

        事件系统  →  游戏机制  →  美术设计
       （发生什么）  （怎么结算）  （看到什么）
              ↘         ↓         ↙
                记忆系统（横向贯穿：世界怎么记得你）
                        ↓
        数据埋点（并联全程：每一步都记，不是最后一环）
模块 本质 一句话职责
事件系统 内容源 提供"发生什么"（剧本与题库）
游戏机制 规则引擎 把内容变成状态变化（结算与推进）
记忆系统 连续性层 让世界记住你，并反过来改变后续内容
美术设计 表达层 上述三者全部变成看得见的东西
数据埋点 测量层 全程记录，喂给报告算法

贯穿一切的原则：每个模块都要同时服务"体验"和"测量"。这是本项目与普通游戏最根本的区别——我们是测评产品伪装成游戏。

二、模块接口契约（谁给谁什么）

从 到 传递什么 形式
事件系统 游戏机制 选项的六维标定、flag、条件修饰符 EventConfig JSON
事件系统 美术设计 场景类型、出场 NPC、情境基调 事件元数据 scene_hint
游戏机制 记忆系统 本次选择产生的 memory_tags 字符串标签数组
记忆系统 事件系统 当前记忆标签（供调度器加权） 标签 → 事件权重
记忆系统 美术设计 记忆墙更新内容（便签/照片/徽章） 见第四章表 3
机制 + 事件 + 记忆 美术设计 当前六维状态（S/O/N/H 可见、D 半可见、R 隐藏） 状态快照（R 不下发）
全部 数据埋点 每次行为的原始记录 12 个埋点事件
数据埋点 报告系统 特征 → 判定 → 报告映射 见算法册

红线：R（隐藏风险）与晋升阈值永不下发前端，美术层也只能表现"有东西在累积"，不能显示数值（见接口 4）。

三、六个结合接口

接口 1：事件 × 美术 —— 场景分区承接事件类型

美术已定义五块区域，正好对应我们的五大事件类别。事件触发时镜头与角色自动切到对应区域，玩家不看文字也知道"这是哪类事"。

区域 常驻 承接 空间语言（沿用美术方案）
开放工位区（中心） 熊技术（王哥） 技术决策类 T1-T6 最亮最暖，屏幕光常亮
洽谈区（右侧） 熊销售（小林） 客户与商业类 C1-C5 沙发茶几，第二亮，制造距离压迫
休息区/咖啡角（左前） 熊行政（小赵） 自我管理类 M1-M5 柔光绿植，失败后被接住的地方
主管区（后景高位） 熊总（老周） 人际政治 P4/P6、汇报 C5、晋升考核 高两级台阶，权威但不遥远
记忆墙（后墙正中+射灯） 熊行政看守 每次记忆更新的高潮时刻 第二视觉焦点

补充：人际政治类（P1/P2/P3/P5/P7）多发生在工位区与洽谈区的交界——因为这类冲突本质上是"协作中的摩擦"，不固定区域，由事件元数据 scene_hint 指定。

接口 2：机制 × 美术 —— 主动探索 = "走到那个区域找那只熊" ★

这是五个模块咬合得最漂亮的一处。

我们在剧情册 V2 定了"每 3 个月 1 次主动探索：花体力找王哥/小林/陈工/小赵/独处"，但一直没定 UI 怎么呈现。美术的场景分区天然就是答案：

探索月不弹菜单，而是玩家在等距地图上走到某个区域—— 去开放工位区找王哥（技术指导）／去洽谈区找小林（需求情报）／去咖啡角找小赵（带教）／去主管区找熊总（向上）／回自己工位独处（自己研究）。

为什么这比点菜单强： 1. 有空间感和仪式感，"主动出击"名副其实； 2. 走动轨迹本身可视化——某人 48 个月总往主管区跑，一眼看出来（社交指纹的视觉呈现，无需图表）； 3. 与埋点天然对接：进入区域即上报 explore_click，区域 ID 就是 target。

成本：复用美术已有的四区域场景，只需增加"玩家角色在区域间移动"的简单位移动画 + 区域热区。

接口 3：记忆系统 × 美术 —— memory_tags → 记忆墙三层

美术的记忆墙已有三层（手写便签 / 拍立得 / 金边徽章）与四条生成规则。需要和我们的 memory_tags 建立完整映射：

记忆标签（机制层产生） 记忆墙呈现 视觉规格 触发条件
「值得信赖的倾听者」 蓝便签 手写体（站酷快乐体） 连续两次选择"先倾听"类选项
「那次伸手」 拍立得照片 关键场景自动截图 帮助同事类选择
「韧性」 金边徽章 记忆金 #EAC26B 重试 ≥2 次后完成
「表达者」 黄便签 手写体 会议主动发言
「被他坑过一次」 灰便签（倒贴） 去饱和、微微歪贴 隐瞒/糊弄类 flag 产生
「好说话」 浅灰便签（边缘卷曲） 手写体、褪色 甩锅时选择"认了"
「替我出过头」 双人拍立得 与 NPC 合影 为弱者发声类选择

关键原则：负面记忆必须上墙。 只记好事的记忆墙是假的，玩家一眼看穿。那些灰便签才是"被记住"的完整含义，也是第 19 月 R2 合规事件里陈工点名的伏笔——墙上早就贴着证据了。

动效沿用美术方案：新便签 0.3s 弹入 + 贴纸音效；负面便签的弹入改为"轻轻贴上、略微歪斜"，音效低半度。

接口 4：机制 × 美术 —— "不透明性"的可视化 ★（最缺、也最有杀伤力）

我们的设计里有一批故意不让玩家看见的东西：R（隐藏风险）完全不可见、晋升阈值隐藏、D 半可见。

美术方案目前没有对应表达。但这里恰恰是戏剧性最强的：

记忆墙旁设一个"上锁的抽屉"（或记忆墙背面）。玩家看得见它、知道它在变沉，但打不开。 每次埋雷类选择 → 抽屉轻微震动 + 一声闷响（无视觉提示内容）。 第 19 月事故引爆时抽屉弹开，里面全是他前 16 个月塞进去的灰便签——第 3 月的 PR、第 7 月的评测集、第 15 月的沉默。

为什么这是神来之笔： 1. 把"隐藏机制"从数值隐藏升级为可视悬念，玩家全程知道有事要发生； 2. 事故爆发时给玩家"原来如此"的冲击，而不是莫名其妙的惩罚； 3. 完全符合"阈值不下发"的安全红线（抽屉不显示任何数字）。

同理，晋升阈值的隐藏可用"主管区门上的进度刻度条"表达——条在动，但不标数字、不标满格在哪。

接口 5：埋点 × 美术 —— 犹豫的可视化（观察者效应）

美术已有"注视跟随"（悬停选项时，眼球先动 80ms、头部随后、身体最后）。与我们的核心埋点 hesitation_ms 结合：

悬停时长 熊的反应 埋点含义
0-2 秒 正常注视 直觉型
3-8 秒 微微歪头等待 正常思考
8-15 秒 眉毛轻抬，目光审视 高犹豫信号
15 秒以上 轻敲桌面 / 熊技术摘下耳机 极高犹豫，标记可能伪装

意义：把犹豫变成可见的社交压力——NPC 在看着你纠结，你更难"演"出一个完美答案。这正是我们要的观察者效应（测量行为本身让被测更真实），也是"伪装者挑战"的体验基础。

报告里的"犹豫地图"沿用同一套视觉语言（同一只熊的同一套表情），玩家瞬间看懂。

接口 6：报告 × 美术 —— 报告页三层重排

美术的报告页原为四层（人格印象 → 能力雷达 → 行为证据 → 岗位建议）。按算法册 §7 的三层结构重排，并补呈现红线：

层 内容 免费/订阅 美术要点
1 一句话人格印象 免费 大字 + 熊总立绘
2 能力雷达（六维，不标数值） 简版免费 沿用美术方案，去掉数字标签
3 大五近似剖面（自评 vs 行为双条对照） 概览免费 双色条形、不标点值、矛盾处高亮记忆金
4 行为证据链（可点开，精确到毫秒/次数） 免费 1 条 卡片式，点开显示原始记录
5 岗位市场参考（真实薪资与要求占比，给数字） 免费第 1 数字卡片 + 标注「来自 5000 条在招 JD」
6 交叉提示：差在哪（行为语言，非数值） 免费 引回具体行为事件编号
7 社交指纹 / 犹豫地图 / 晋升轨迹 订阅 地图轨迹图复用场景美术

视觉红线（V3 新增，美术必须遵守）： 1. 特质条形一律不标数字——只用长短 + 五档词（很低/偏低/中等/偏高/很高）； 2. 雷达图不标数值； 3. 差距区标注用行为语言（「没人监督时」），不标「−2.2」； 4. 晋升/风险永不出现阈值或「还差多少」； 5. 市场数据区必须给真实数字并标注来源——这是整份报告可信度的锚。

五、三个冲突及解决

冲突 1：NPC 名字对不上

美术「熊总/熊销售/熊行政/熊技术」vs 剧情「王哥/陈工/小林/老周/小赵」——已解决，见表 1。需同步给美术与策划双方。

冲突 2：职业选择页有五张职业卡，但已锁死一条线

我们在 V1.1 已锁死 Agent 开发师一条体验线（其他线不做剧情）。美术方案仍设计"五张职业卡：主题色带+代表物件+职业印象+挑战标签"。

解决方案：改成「入职 Offer 页」—— - 保留美术的全部视觉元素（主题色带、代表物件、职业印象、挑战标签）； - 但只展示 Agent 开发师一张卡的放大版，作为"你收到的入职通知"，而非五选一； - 其余四张的美术素材不浪费：降级为页面背景中的虚化卡片（暗示世界上还有其他职业），视觉丰富度保留，但不构成可点选项，也不构成承诺。

这样既不违背"锁死一条线"的产品决策，又不推翻美术同学已完成的设计工作量。

六、完整链路演示：一次点击如何走完五个模块

用真实案例串起来（第 7 月，评测集事件 T2）：

  1. 事件系统：调度器判定 L2 阶段、前置 T1 已完成 → 触发 T2（月度主线），scene_hint = 开放工位区，出场熊技术（王哥）。玩家看到时间卡片「第 7 月 · 你已经能独立负责一个模块了」。
  2. 美术设计：镜头切到开放工位区，屏幕光常亮，王哥挂着耳机偶尔抖腿（待机动作）；三个选项浮出。
  3. 玩家犹豫：鼠标悬停"B 先不建"上 —— 王哥眼球先动 → 转头注视 → 8 秒后眉毛轻抬（接口 5）。埋点记录 option_hover 与停留时长。
  4. 玩家点击：option_click 上报（含 snapshot_before）。
  5. 游戏机制：服务端 <50ms 结算——O+2、S−1、风险 +3；判定当前情境为"中"（工期紧），记入行为序列。
  6. 记忆系统：产生 memory_tag「求快」，写入王哥的记忆列表；记忆墙新增一张浅灰便签（接口 3）；同时上锁抽屉轻微震动一声（接口 4）。
  7. 美术反馈：王哥"收起热情，说再来一次"（负向反馈），无红叉、无扣分提示（美术铁律）；日夜状态若触发加班则 10s 渐变入夜，熊技术打哈欠配合。
  8. 埋点归档：task_complete 汇总月度数据；风险累积 +3 进入晋升行为层。
  9. 后续兑现：第 22 月 C4 客户 Demo 事件，因 T2 未建评测集，翻车概率上浮——五个模块的因果闭环在这里合拢。

这条链路的意义：五个模块不是各做各的，而是同一次点击在五个层面同时发生。任何一环缺失，体验或测量就会断。

七、待确认事项

  1. 陈工是否接受"熊技术变体"方案（+0.3 成本），还是坚持做第五只独立形象（+1 成本）？
  2. 上锁抽屉的美术实现成本（需美术同学评估：震动 + 弹开动效约 1.5-3s）。
  3. 主动探索的移动交互：是自由行走（成本高）还是点击区域热区直接切镜（成本低）？建议先用后者，决赛版本够用。
  4. 「入职 Offer 页」改造需与美术同学确认工作量。
