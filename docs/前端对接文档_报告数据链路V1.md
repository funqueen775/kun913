# 熊心壮职 · Agent 开发师 — 前端对接文档：报告数据链路 V1

对应《报告数据链路与算法设计 V2.3》（算法册）、`contracts/openapi.yaml`（接口唯一准则）、
`contracts/fixtures/report-ready.json`（报告样例）。本文件只讲前端要做的两件事：
**把玩家看到的渲染出来、把玩家做的原样上报**。

> 口径依据：算法册 V2.3 §2（埋点）、§6（报告呈现）、§9（落地清单）。
> 接口字段冲突时以 `contracts/openapi.yaml` 为准，改字段必须同时改 fixture。

---

## 1. 总链路一张图

```text
玩家点击选项
   ↓ ① 前端上报原始行为（17 个埋点：什么时候点的、犹豫多久、横跳几次）—— 本文 §3
   ↓ ② 服务端结算（打分卡累加：六维/能力/大五/专题）—— 后端已实现，前端不可见
   ↓ ③ 服务端测量（贝叶斯后验、专题聚合、雷达、投入结构）—— 后端已实现，前端不可见
   ↓ ④ 服务端报告（三层 × 13 模块）—— 后端已实现，前端只渲染 —— 本文 §4
```

**前端不在链路里出现任何一次计算。** 打分卡（`scoring_cards.json`）任何内容不得下发前端、
不得进客户端代码与配置——抓包能拿到标定答案，整套测评直接被破解（算法册 §1 红线）。

## 2. 三条红线（写代码前先读）

1. **客户端不算分**：客户端本地任何六维/能力/大五数值只允许是「服务端回包的展示」，
   不允许本地推导；本地预览分不落库、不参与任何判断。
2. **阈值永不出现**：报告 JSON 里 `threshold` 字段仅供内测对账，**客户端一律不渲染**；
   报告文案里不会也不该出现任何门槛数字，前端不要自己补。
3. **证据不足就静默**：`displayable=false` 的模块、空数组的字段，**整块不渲染**，
   不要显示「暂无数据」占位——测评报告里「没说」本身就是设计（算法册 §6：证据不足就不说）。

## 3. 埋点上报（前端 → 后端）

### 3.1 通用事件信封

所有埋点走同一个接口（M4 上线前先按此格式缓冲，见 §3.3）：

```json
POST /api/v1/sessions/{sessionId}/events
{
  "eventId": "uuid-v4",
  "eventType": "option_click",
  "contentVersion": "v1",
  "clientTime": "2026-09-14T20:30:00+08:00",
  "payload": { }
}
```

- `eventId`：客户端生成，幂等键——同 eventId 重复提交返回上次结果，重发是安全的。
- `contentVersion`：内容版本，当前 `v1`。

通用 payload 字段（所有埋点都可带）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| regionId | string | 当前区域 A–H |
| hesitationMs | int | 进入决策点到确认的毫秒数，**原样上报，客户端不做任何加工** |
| switchCount | int | 选项间横跳次数（hover/焦点切换计数） |
| snapshot | object | 选前状态快照（精力/金钱/职级等公开账本字段），校准对账用 |
| skip | bool | 是否跳过（manual_read / achievement_view 用） |

### 3.2 十七个埋点：时机与字段

| # | eventType | 什么时候上报 | payload 专属字段 | 服务端拿来干什么 |
| --- | --- | --- | --- | --- |
| 1 | profile_start | 建档开始 | — | 测评起点 |
| 2 | profile_answer | 每答一题 | questionId、选项、耗时 | 自评先验（贝叶斯的「病人自述」）+ 敷衍检测 |
| 3 | manual_read | 第 1 月读手册 | 章节、时长、skip | 动机信号（反复看「晋升通道」vs 跳过） |
| 4 | event_trigger | 事件触发 | storyId、命中原因、权重快照 | 「这个事件为什么找上你」可解释 |
| 5 | node_enter | 进入决策点 | storyId | 犹豫时长计时起点 |
| 6 | option_hover | 选项悬停 | storyId、choiceId | 横跳计数 |
| 7 | option_click | 选项确认 | storyId、choiceId、hesitationMs、switchCount、snapshot | **主数据源**：DecisionLog 一行 |
| 8 | allocation_click | 月度精力分配 | templateId、分配向量 | 价值排序、投入结构 |
| 9 | explore_click | 自由周末 | activityId、类型(work/social/solo)、同伴 npcId、天气 | 投入结构 + 内在动机 + 冲刺检测 |
| 10 | survival_state_change | 生存轨状态变化 | 从什么状态到什么状态、原因事件编号 | 处境轨迹模块 |
| 11 | crisis_talk_choice | 危机对话 | 归因选项、hesitationMs | 归因指纹（第二层） |
| 12 | monthly_action_variant | 月度轻节点 | 变体类型（含「看娃」） | 日常负荷 |
| 13 | achievement_view | 成就节点 C1/C2/C3 | 停留时长、skip | 成就参与度（C1/C2/C3 是纯演出无选项） |
| — | （C4/C5 走 option_click） | 成就节点 C4/C5 | 同 #7 | C4/C5 是轻决策点，产出大五/SDT 证据 |
| 14 | zone_dwell | 进出组团 | 组团 id、进出时间 | 空间偏好（彩蛋） |
| 15 | ai_reaction_view | 反馈查看 | 时长 | 沉浸度 |
| 16 | task_complete | 结束 | 汇总 | 沉浸度 |
| 17 | report_view | 报告浏览 | 浏览顺序、各模块时长 | 报告优化（哪些模块没人看） |

**新增系统只记不用**（熊友卡协助、训练谷对局、家园购买摆放、NPC 主动消息、关系阶段变化、
月度经济结算、训练谷邀约）：全部只落日志、不进测评。原则：**宁多记、不算账**——
原始数据永远可以事后重新算。

⚠️ **训练谷重试与主线重试分表存储**（训练谷无惩罚可无限重试，共用计数器会污染主线的
「完美主义」信号）——上报时 eventType 带来源区分，不要混用同一个重试计数。

### 3.3 上报规则

- **M4 上线前**：用本地缓冲模式攒队列——客户端只做 `report(type, payload)` 打点，开发期打控制台即可；接口通了接 `flush()` 批量提交。
  （原 React 原型里按 `web/src/api/report.ts` 实现该模式，`web/` 前端已于 2026-09-19 删除，Godot 侧照此模式实现，别复刻整套。）
- **失败重试**：同 eventId 重发是安全的（服务端幂等，返回上次结果）；队列持久化到本地存档。
- **断网**：不阻塞游戏流程，先进本地队列，恢复后按 seq 顺序补报。
- **不要做**：不要在客户端算犹豫分段、不要给事件去重、不要丢弃你认为是「重复」的埋点——
  服务端自己判断。
