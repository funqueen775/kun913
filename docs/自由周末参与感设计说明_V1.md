## 1. 现状诊断（都在代码里，不是感觉）

| # | 现象 | 证据 |
|---|---|---|
| 1 | 一个周末 = 两次点选 + 一次结算，玩家没有"安排"这个动作，只有"选择" | `FreeTimePanel.choose_zone()` → `choose_activity()` 走到底；`choose_activity()` 里当场 `apply_weekend_activity()` |
| 2 | 结算是账本口吻，且**违反自己写的红线** | `MonthlyLife.apply_weekend_activity()` 产出 `"%s 好感 %+d"`，直接进 `_show_event()` 展示 |
| 3 | 同行者是骰子 | `FreeTimePanel.auto_targets()` → `candidates.pick_random()`，卡面写"随机同行" |
| 4 | 结果没有回声，关掉面板世界不动 | 周末只写 memo（且只有雨天 D6 写），没有任何读取端 |
| 5 | 没有累积物，16 个周末过完手上空 | 记忆墙是主线便签，没有"我的周末"容器 |

结论：1 和 3 是设计问题，2 是红线问题，4 和 5 是"缺回声"。四件改动对应处置。

## 3. A · 自己排（周六 2 格）

> ⚠ 结构口径以 §13.1 为准：一个自由周末 = **周六 2 格 + 周日自由**。
> 本节原写"三格 / 三段 / 周六上午+周六下午+周日"，2026-09-16 按 §13.1 重写为两格版。

### 3.1 交互

- 首屏不再是"出门逛逛"按钮，而是**一张两格空表**：`周六上午 / 周六下午`，每格显示"还没安排"。
- 点某一格 → 走现有二级路（选区域 → 选活动，复用 `_show_zones()` / `_show_activities()`）→ 填回该格，**不结算**。
- 已填的格可点开**改**或**清空**（清空 = 恢复留白）。
- 两格都排完（或不想排了）→ 底部「就这样过」→ 一次性结算 → 手账页。
- **留白是有效选择**：不提示、不惩罚、不追问，手账上就写"留白"。
- **周日不在这张表里**：没有日程、不出结算面板、不铺引导线（§13.1 三条红线）。

### 3.2 状态机（改 `FreeTimePanel._step`）

| 值 | 界面 |
|---|---|
| `closed` | 隐藏 |
| `slots` | 两格总表（新首屏） |
| `slots_zone` | 为第 `_editing_slot` 格选区域 |
| `slots_activity` | 为第 `_editing_slot` 格选活动 |
| `encounter` | 在场一幕 + 一次应答（B，已落） |
| `ledger` | 周末手账页（C） |

`_slots: Array[Dictionary]`，**长度固定 2**，每格 `{slotId, zone, activityId, activity, targets, labels}`。
格 id 固定 `sat_am / sat_pm`，显示名 `SEGMENT_LABELS := ["周六上午", "周六下午"]`。
（`sun` **不再是一个格**——周日没有额度，见 §13.1。）

### 3.3 关键决策（不是遗漏，是故意的）

- **一个周末最多演一次决策点**。`free_time_system.json` 里 D2/G1/G2/G4 带 `decision`；两格可能有多个，
  连着问两次会烦。取**第一格带 `decision` 的活动**演，另一格降级为普通结算，理由写进手账
  （"那天后来又聊了两句"）。保底：一句台词换掉一次弹窗。
- **不做格子间依赖**（"先自习再自习才触发 X"）。V1 只要组合效果，不做链式条件——链式一上，玩家就开始查攻略。
- **同一个活动在一个周末只能出现一次**（§13.2 拍板）。原稿写的是"三段可以同活动、靠收益递减兜底"，
  两格制下这条不成立：两格都填收益最高的那个活动，永远打赢"尝试新东西"，而周末的全部意义是**投入结构**。
  落法：`slots_activity` 列表里把已填进另一格的活动置灰不可选。收益递减继续对**同 NPC**生效，两者不冲突。

### 3.4 组合效果判定表（两格版）

只用 `free_time_system.json` 已有的 `input_type`（`work / social / solo_recover / solo_work`）聚合，**不新增任何数据字段**。

| 两格组合 | 判定键 | 效果 |
|---|---|---|
| 两格都是 `work` / `solo_work` | `all_work` | H−1；落 memory_tag「闲不住的人」；C 锚点 |
| 两格都是 `social` | `all_social` | 归属满，H−1 |
| 两格都是 `solo_recover` | `all_solo` | H+1；autonomy 锚点 |
| 一格 work、一格 `solo_recover` | `balanced_default` | **无附加**（平衡是默认值，不奖励） |
| 一格 `social`、一格 `solo_recover` | `people_and_self` | H+1 |
| **两格同区域** | `same_zone_focus` | 该区域**首个**活动收益 +1（一次） |
| 任一格留白 / 只填一格 | 不参与组合判定 | 留白只记入投入结构，不加不减 |

> 优先级：`all_*` > `people_and_self` > `balanced_default`；`same_zone_focus` **独立叠加**。
> 两格制下 `same_zone_focus` 的触发条件即"两格同区域"（原稿"两段及以上"在 3 格制下才有意义）。
> 落点：新增 `MonthlyLife.weekend_combo(slots) -> {key, lines, state_delta}`，纯函数、可探针直测。

## 4. B · 有脸的人（二期）

**不加回"选人环节"**——同行者仍由系统指派。改的是把骰子变成**在场一幕**：

1. 先一屏场景：「你在外摆的椅子坐下，抬头看见 **小林** 端着咖啡站在门口，他没看见你。」（头像用现有熊图集首帧，`StoryEventPanel` 已有同一套取法）
2. 再一个应答按钮组（2–3 选 1）：「招呼他坐过来 / 点点头 / 低头看手机」。

**这是性格测量，不是好感度博弈**：好感度照旧按活动配置的固定值走，应答只决定 `marker`、SDT 分、`memory_tag`、以及之后 NPC 回召哪句台词。

| 活动类型 | 在场者 | 玩家动作 | 落什么 |
|---|---|---|---|
| `solo` / `work` | 无 | 不演一幕，手账多一行「这段最舍不得结束」式批注 | 手账批注 + 锚点 |
| `duo` | 随机 1 人 | 见面对话 2–3 选 1 | `marker` / `memory_tag` |
| `group` / `team` | 随机 2 人 | 场合里表态 1 次 | `memory_tag` |

**只演一次**：两格填满并点「就这样过」后，按「decision 优先于 encounter」挑一格演在场（两格都有可演内容时先演排在前面的那格），另一格的同行者只出现在手账行里（"那晚后来又聊了两句"）。一屏一次，不啰嗦。

### 7.3 埋点（哪些要埋、埋成什么）

原则：**埋点只记"玩家做了什么 + 在哪犹豫"，不记"系统算出了什么"。**

| 新机制 | 埋成什么 | 归属报告模块 |
|---|---|---|
| 排格（把某格给谁 / 给什么） | **`allocation_click`** | 价值排序 + 投入结构 |
| 留白（某格故意空着） | 同上，payload 带 `skipped: true` | 留白率 |
| 每格最终选的活动 | `explore_click`（已有，payload 待修） | 投入结构 |
| 在场一幕的应答 | **`option_click` + `npcId`**（复用，不新造 `encounter_choice`） | 摇摆 / 犹豫 |
| 手账页停留时长（可选，二期） | `ai_reaction_view` | 沉浸度 |

**不埋**：组合效果（系统对分配的解释，不是玩家行为，埋了就是重复计数）· 玩家手写那句话（自由文本进证据库会污染标注，还会顺着 LLM 润色进 prompt，正踩 `free_time_system.json:2` 红线；只归本地手账 + 记忆墙）· 回声消费与手账册翻阅（回放不是行为）。

`allocation_click` 是本次改造**唯一能补上的契约空白**（契约注释原文："月度精力分配：分配向量 → 价值排序"，Godot 至今零发送）。两个天然落点：能量面板的四个行动按钮、周末的填格与留白。

**现状盘点**：契约 17 个测评事件，Godot 实际只发 **6 个**（`event_trigger` / `node_enter` / `option_hover` / `option_click` / `explore_click` / `zone_dwell`）。**从未发送的 10 个**：`profile_start`、`profile_answer`、`allocation_click`、`survival_state_change`、`crisis_talk_choice`、`monthly_action_variant`、`achievement_view`、`ai_reaction_view`、`task_complete`、`report_view`——都要等对应模块（建档、生存轨、危机对话、月度轻节点、报告页）做出来。**不要为"埋点齐全"自造事件名**：`server.py` 不校验白名单，落库不报错，但报告侧永远读不到，等于埋了个寂寞还污染事件流。

**改造前必须修的三处既存不合规**

1. **`explore_click` 一开 live 就被 400 拒**。`server.py:350-352` 对**每个**事件强制 `payload.regionId` 匹配 `^[A-H]$`，而 `FreeTimePanel.gd:248` 发的 payload **没有 `regionId`**，`zone` 还是 `"D_树影书院"` / `"心湖"` 这类字符串。`mode=mock` 时只是排队、看不出来；一开 live，每个自由活动埋点都会进 `workplace_town_api_rejected.jsonl`。
   修法：补一张 zone→字母 反表（`WorkplaceTown._zone_by_code` 只有反方向），把 `regionId` 加进 payload。**前置决策：心湖 / 心湖步道 算哪个字母**（见 §12）。
2. **`weekend_close` 不在枚举里**（`WorkplaceTown.gd:1606`）。要么在 openapi 的"叙事流补充"里加一行，要么并进 `explore_click`。
3. **`handbook_read` 名字错**（`WorkplaceTown.gd:1968`），契约里叫 `manual_read`。

其余埋点（`option_click` / `event_trigger` / `node_enter` / `option_hover`）的 `regionId` 取自 `WorldClock` 的 `locationId`，本身就是 A–H 单个字母，**合规**——唯一破口是 `FreeTimePanel` 那一条。

### 13.1 周末结构：三段 → 「周六 2 格 + 周日自由」

> ⚠ 本条与 §0 第 1 行（"3 段"）冲突，**以本条为准**；§0 第 1 行已同步改写。

| | 工作日 | 周六 | 周日 |
|---|---|---|---|
| 单位 | 体力 4 点 / 天 | 日程 **2 格** | 自由时间，没有日程 |
| 消耗 | 做什么都 −1 点 | 每填一格占一格 | 不扣任何东西 |
| 结算 | 即时 + 推进一个时段 | 周末结束一次手账 | 不出结算面板 |
| 进报告 | 是 | 是（投入结构唯一来源） | **否**，只落 `zone_dwell` 轻轨迹 |
| 可留白 | 是 | 是（留白有语义） | — |

**为什么不能"想干什么都行"的无限额**：① 玩家一旦发现"全选收益最高"，策略坍缩成机械点满，稀缺消失 → 没有排序证据（`allocation_click` 是价值排序 + 投入结构的唯一来源）；② `report_line`（「16 个自由周末，你 N 次给了技术…」）会变成谁都一样；③ 留白率（比投入结构更锋利）在无限额下不存在。

**为什么也不照搬工作日的体力**：4+4=8 点等于两天工作日量，周末就不特殊了；8 次点选必然开始重复（S 类只有 4 个活动）；与"体力"语义重复（玩家会算 4+3=7 两笔账）；引擎锚点是"3 点不可结转"，做成资源条连跨期收益都没有。

**周日自由时间的三条红线**：✅ 走遍小镇 / 找 NPC 闲聊 / 湖边天台坐下待一会儿（可留一句字进手账）/ 开记忆墙 / 回家睡觉；❌ 填格触发活动（只在周六）；❌ 落 `explore_click` 或进 `events.jsonl`（只落 `zone_dwell`）；❌ **周日闲聊不加好感度**——一旦能加，玩家会把周日当成刷好感的资源，"什么都行"退化成更硬的日常任务。

**需要补的最低内容**（否则"什么都行"是空跑）：5 个 NPC 各 1–2 句周日闲话（现在 `_dialog_label` 工作日与周末同一句、6 秒消失）· 湖边 + 天台各一个"坐下"热点 · 周日不出任务卡、不铺引导线（与"地上的线只报此刻"一致）。

**✅ 内容侧落地（2026-09-17 下午）**：
- **周日定义**：世界里没有星期几——「周日」= 周末面板收束的次日（`_sunday_day_index`，收束时 dayIndex+1 记下，`_is_sunday()` 判等）。
- **5 人周日闲话 ✅**：`npcs.json`（演员表唯一来源）每人加 `sunday_prompt` 数组（2 句），schemaVersion 1→2；`_begin_interaction` 周日随机挑一句说。**纯台词不加好感**（红线：加了周日就退化成刷好感的资源）。
- **坐下 ✅（MVP 版）**：湖边（心湖）与天台（A_总部）同在 A 区 → 周日进 A 区即触发一次坐下（`_maybe_show_sunday_sit`，按 dayIndex 奇偶轮换湖边/天台文案，一个周日一次），复用对话条 8 秒；只落本来就有的 zone_dwell。**与原案差异**：不是可走到的独立热点，而是"进区即坐下"——真热点要动世界物件与交互系统，等并行会话的训练谷收口后再升级。
- **周日不出任务卡、不铺引导线 ⏳ 未做**：任务卡/引导线正被并行会话重构（guide_line 的 8 个 FAIL 就是它改了任务卡指向「H 区宿舍睡一觉」），此时补会撞车，等它收口。

### 13.4 A / C 件实现时定的四个细节

判定表没覆盖到的地方，按"最小惊讶 + 不新增数据/键"定，**都可改**：

| # | 细节 | 定法 | 为什么 |
|---|---|---|---|
| 1 | 组合效果的类别从哪来 | 顶层 `input_structure.categories` **反查** activity_id → 类别 | 活动自己**没有** `input_type` 字段（19 个全是 null），而 §3.4 要求"不新增任何数据字段"——反查是唯一不新增字段的做法 |
| 2 | `work + social` 两格 | 落 `balanced_default`（无附加） | §3.4 只写了"work + solo_recover → balanced_default"，没写 work + social。**不新增第 7 个组合键**，保持 6 键口径 |
| 3 | `same_zone_focus` 的"收益 +1" | 取**首个活动 `gain` 里数值最大的那一项** +1（`gain` 为空则按生命） | 原话"该区域首个活动收益 +1"没指定币种；这样不会凭空造出一个活动本来没有的收益 |
| 4 | 一格留白、另一格填了 | 不参与组合判定 | §3.4"含留白 → 不参与组合判定"的直接推论：两格制下"含留白"就是"只填了一格" |
