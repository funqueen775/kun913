# 熊心壮职 · 前端

进入游戏前的开场三屏。React 18 + Vite 6 + TypeScript，零运行时依赖（没有 UI 库、没有状态库）。

## 跑起来

```bash
npm install
npm run dev        # http://localhost:5173
npm run typecheck  # 类型检查
npm run build      # 产物落 dist/
```

后端是 `backend/engine_core`（Python 引擎内核，M4 阶段才接 FastAPI，默认 8000）。
`/api` 已在 `vite.config.ts` 里代理过去 —— 注意 **M4 之前没有可代理的服务**，dev 下 `/api`
请求会失败，这是预期状态（开场三屏不需要后端）。

## 本目录里的「占位稿」（不是美术资产）

原型里有两种东西是我方（AI/程序）做的临时稿，**美术组交付前不得当成正式素材**：

| 占位稿 | 位置 | 什么时候该被替换 |
| --- | --- | --- |
| 五只熊的头像 | `src/components/BearAvatar.tsx`（SVG 手画） | 美术的熊纸娃娃图集或头像 PNG 到位后，换成 `<img>` |
| 标题底图 | `public/art/title-bg.jpg`（AI 生成） | 美术交付 `assets/ui/intro/title_bg.png` 后 |

美术正式资产的落点是 Godot 工程：`assets/ui/intro/`（见那里的 README）与
`assets/characters/paper_doll_64/`。**原型目录里的图不要反向搬进 `assets/`。**

## 深链

评审时可以直接把某一屏某一页发出去：

```
/?screen=title
/?screen=town&page=2
```

`page` 从 1 开始。只在最后拼上，不影响正式流程。

## 三条纪律

1. **前端只渲染 + 只上报原始行为。** 一切计算在服务端。客户端一旦能算出分数，抓包即拿到标定答案，测评直接被破解（《后端开发方案 V1》§1）。
2. **不在组件里写死色值**，只能引用 `src/styles/tokens.css` 的变量。
3. **画风三件套**：均匀深棕描边（不写粗细变化）、平涂（禁渐变噪点）、UI 沿用地图的「扁平插画厚度」。

## 版式约定（照用户给的三张开场参考图定，改动前先看）

- **按钮是小圆角、近乎平的**：`--xz-radius-sm` = 6px，厚度只有 2~3px 的底边（`--xz-bevel-dark`），**不要**再堆厚实的立体投影。
- **不用胶囊**。存档条 / 页码 / 底部提示统一用 `Plate`（方角细边的小牌）——参考图里没有胶囊。
- **第 1 屏是上下两块独立的牌**：上面「瓦顶 + 横幅」的标题牌（`Roof` + `.title-screen__banner`），下面菜单牌（`.title-screen__menu`，顶上镶一颗 `Gem`）。不要合并成一块。
- **标题牌上只有四个字**。副标题（Agent 开发师 · 48 个月）和存档条（小熊镇 · 第 1 年 第 1 月 · L1 新人）**用户已要求去掉**，不要再加回来——标题页不报进度，存档信息留给游戏内。
- **不要往画面上加任何标注文字**（例如「第 1 屏 · 标题主菜单」那种角标）。用户明确说碍眼。深链本身就能定位屏与页。
- **第 2/3 屏是「深棕木质雕花框 + 羊皮纸」**：外壳用 `ParchmentFrame`（顶部 `Crest` 钟楼、四角 `LeafSprig` 藤叶），内容是羊皮纸。内外色差是质感的关键，别把外框也做成米黄。
- 页签很小很矮（36px），标题条 / 状态条和 50px 的行高对齐。

## 设计稿基准

1600×900，正好等于地图原生分辨率，**不要**改这个尺寸去适配屏幕；适配交给 `Stage` 的 `useStageScale()`。

`layout` 参数控制构图：

- `left`（默认，已选）：面板靠左，露出心湖 + 熊石雕塑，雕塑是这张地图的视觉主角。
- `center`：还原参考图的居中构图，但会把雕塑盖住。

### 第 3 屏的外壳（2026-09-13 改）

第 3 屏**必须沿用第 2 屏的 `ParchmentFrame`（深棕木框 + 羊皮纸）和同一套顶栏**（返回 168px / 标题条 / 状态牌 112px，行高 50px），切换屏时不该有跳动。

已被否掉的那版：浮在左边的小面板 + `Roof` + 一颗「待做」**胶囊**徽章 + 虚线分隔。
问题有两个 —— ① 那是第 1 屏标题牌的语言，混进来显廉价；② 胶囊违反 `tokens.css` 的「不用胶囊」（存档条/页码/提示统一用 `Plate`）。
存档信息按用户要求从标题页挪到了这一屏的存档行（标题页不报进度）。

### 没有「选择初始同事」这一屏（重要）

**五位同事是游戏里写死的，玩家不选人。** 开场只有两屏：标题主菜单 → 认识小熊镇。
曾经做过一版「选择初始同事」，已整屏删除（源码归档在 `web/.trash/`）。不要再加回来。

第 2 屏的「人物名单」页就是**只读的人物档案**：让玩家看清五位 NPC 的基本情况，
不做任何选择。版式是整屏五张卡并排（`.cast-card`），**不要**塞进左边小框里跟插图并排——
那样五个人挤成一列根本看不清。

### 第 2 屏的口径（改动前先看这里）

- 大标语「**熊有熊的活法**」+ 正文首句「镇上的熊，都在忙自己的事」——用户 2026-09-11 定稿，前两版偏"压力"的写法已被否掉。
- 人物名单页大标题「**五位同事，五种立场**」——用户 2026-09-12 要求贴近职场，否掉了原来的「五只熊，五种脾气」。
- **玩家按"是一只熊"来写**（片名「熊心壮职」是"雄心壮志"的谐音，NPC 全是熊X，熊友卡、湖心熊石雕塑都指向这条）。这条需向美术负责人核对《小熊镇世界观 V1.1》，目前是待确认状态。
- 另外两页的插图全部裁自地图本身，**不要另画插画**——另画是最容易跑味的地方。
- 人物名单里陈工带「不进关系系统」徽章：机制上的例外，用一枚小徽章说清楚，边界本身就是叙事。
- 名单页的五张卡必须**顶部对齐**（`justify-content: flex-start`）：陈工多一枚徽章，居中的话五张卡头像会不在一条线上。
