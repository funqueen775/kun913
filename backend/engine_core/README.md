# 熊心壮职 · Agent 开发师 —— 后端工程

对应剧情册 **V5.27**、算法册 **V2.3**、机制文档《游戏机制与情绪价值设计说明 V1》。
后端总目标只有一个：**把「玩家点的每一次选择」变成报告里那句「被看穿了」的话**，且全程可复算、可对账。

技术栈：Python 3.13 + FastAPI（M4 接入）+ SQLAlchemy / SQLite（M4 接入）。
当前 M0/M1 阶段**不依赖任何第三方库**，只用标准库，直接可跑。

---

## 一、分层

```
core      配置层   加载 5 份 JSON，构建期校验（唯一口径，不含任何标定数值副本）
engine    引擎层   48 个月推进、结算、晋升三层、生存轨、危机对话
measure   测量层   大五贝叶斯、六专题模型、雷达、投入结构          ← M2（已实现）
report    报告层   三层 × 13 模块 + 守界者双计数器                ← M3（已实现）
api       接口层   REST + 持久化（7 张表）                        ← M4
```

## 三、怎么跑

```bash
cd xiongxinzhuangzhi/server

# 2) 48 个月跑批
python scripts/simulate.py                          # 按编号顺序选（回归基线）

python scripts/simulate.py --policy utility --json out.json
```

## 四、已实现（M0 + M1）

- 配置层：5 份 JSON 加载、版本读取、结构计数、便捷访问器
- 构建期校验：loading 回退、flag 完整性、危机对话、守界者计数器、时间口径、
  结构性计数、雷达满分复算、专题覆盖面
- 引擎层：**48 个月完整跑通**，四种策略均无异常；核心选择数精确等于 103
  （39 主线 + 48 月度 + 16 自由周末），与算法册 §1 口径一致
- 结算链：六维（D 走 pending 月末结算）、能力、大五加权载荷、SDT / 调节焦点 /
  道德基础 / 归因 / CFC / NFC、flags、memory_tags、psych_drive、公开账本、好感度
- 时间口径：`DecisionLog` 落 `seq`（相对序号）+ `month`（游戏内月份）+ `rest_month` 标记
- 机制联动：风险累积引爆事故、H 归零倦怠事件（一次倦怠期只记一次）、
  生命归零 → 下月强制休息 + 主线顺延、月度休息递减表、自由活动收益递减与知心时刻

### M2/M3 已实现（2026-09-14）

- **测量层**（`app/measure/`）：贝叶斯后验 `后验 = 自评 + K×(行为分−自评)，K=n/(n+5)`，
  行为分按 `MID + DEV_MAX × mean(dir×coef) × loading_base` 对中点等比缩放（复现算法册 §4 的 3.5→4.1）；
  矛盾度阈值判定；跨情境一致性（situational →「你的 X 是有条件的」）。
  六专题聚合含分场景拆解（调节焦点日常 vs 事故）、单弦门槛（道德基础）、
  归因双层（E19 命中即引用 + 危机对话对照）、psych_drive 命中即高光。
  雷达满分与校验器同算法（实算 40/37/35/34/30/8）。投入结构 = work 占比 × 自愿系数。
- **报告层**（`app/report/`）：三层 × 13 模块一次成形，输出即契约形状（camelCase），
  呈现铁律落地：推断值给五档词不给点值、阈值不出现在文案、证据不足模块整体消失。
- **验证**：index/utility/random 三策略端到端出报告；
  `python scripts/simulate.py --policy random --seed 7 --report out.json --self C=7,A=6`。

## 六、待确认清单（后端已把问题挑出来，等拍板）

1. **雷达满分口径对不上**（校验器 B 段）
   算法册 §9 记 40/33/33/31/23/14，按 `scoring_cards.json` v2.9 实算为
   **40/37/35/34/30/8**。其中「原则底线 40」完全吻合，说明算法正确、是表值旧了。
   **抗压韧性差得最多（8 vs 14）**，疑为 v2.4 期旧值。需二选一：改文档，或补标定。
   另：11 个能力键 → 6 根柱的具体归属也没有明文，`constants.RADAR_MAP` 是语义默认值。

2. **调节焦点有 5 个选项未标**
   E04（2 个）、E23/E26/E27/E30（各 1 个）未标促进/预防。总数 21、8/13 的分布与
   文档完全一致，但**选到这些选项的玩家在该题少一次观测**。建议补标，或明确
   它们是「第三类：不适用」。

3. **生存轨的 6 个月阈值与 6 个月考核窗打平**
   自我修复阈值 = 连续 6 个月无新增失误；考核窗间隔 = 6 个月。实测中玩家累计 3 次
   失误，但每次刚够 6 个月就被自愈抹掉，**永远不会进入「观察」档**。
   要么把自愈阈值放宽（如 8–9 个月），要么让「同一类型的重复失误」不清零。

4. **晋升三层判定的阈值全部是占位值**
   剧情册只写了权重（70/20/10）和「三层全达标」，没给任何数字。
   `promotion.PLACEHOLDER_CUMULATIVE_MIN` 等三个常量是占位值，**必须由机制层校准后替换**。

5. **逐月排期是引擎默认值**
   剧本只给了「五幕 + 职级解锁」，没给「第几月出哪个事件」。
   `timeline.ACT_WINDOWS` 是默认排期（按幕窗口均匀铺开），改这一个字典即可，不动引擎。

6. **项目阶段解锁的口径需要一句话确认**
   剧情册 §四说 39 个主线事件「全部必遇」，§2.2 又说「项目阶段由职级解锁」「不升职，
   项目就被别人推进」。当前实现是**时间轴驱动（必遇）+ 只记 `role` 标记**——
   即事件照常发生，但玩家以什么身份参与由职级决定。若设计意图是「没升职就真看不到
   后续事件」，需要改调度器。

7. **3 个自由活动有标签但无打分标记**
   `S1_library_study` / `D1_coffee_chat` / `D3_lawn_sports` 有 `bigfive_proxy` 标签
   （"C+" / "A+" / "E+"）但没有 `markers`，等于**不进大五证据**。补 markers 即可。

8. **公开生命的扣减规则在机制层**
   当前引擎只消费选项的 `life` 白名单字段与月度休息；「连续加班 / 事故处置」对公开生命的
   扣减按剧情册归机制层。缺了这块，跑批里生命始终是满的，强制休息月永远不会触发。

## 七、口径红线（写在代码注释里，改代码时别踩）

- 前端只上报原始行为，**所有计算在服务端**；`scoring_cards.json` 任何内容不得下发前端、不得进 prompt
- 公开账本与隐藏账本**字段完全不同、互不读写**；公开生命 ≠ H，公开专业能力 ≠ S
- 六个专题模型**只进报告专题模块**，不进大五、不给综合分；证据不足就不说
- 四条防污染：主线不锁选项 / 增益不增证据 / 娱乐不做判断 / 奖励不指向唯一最优解
- 统计与跨玩家对齐一律用 `seq`，只有剧情时间卡片与本玩家证据引用用 `month`
